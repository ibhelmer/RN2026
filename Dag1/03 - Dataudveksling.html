08 · Dataformat

XML: data med start- og slutmærker

EKSEMPEL · XML
<aftale>
  <navn>Anna Jensen</navn>
  <afdeling>Kardiologi</afdeling>
  <tid>13:15</tid>
</aftale>
XML = et dataformat
  • Beskriver oplysninger med tags
  • Er struktureret og tydeligt
  • Bruges i mange integrationer
XML er ikke et selvstændigt system eller en måde at sende data på.
09 · Dataformat

JSON: data med feltnavne og værdier

EKSEMPEL · JSON
{
  "navn": "Anna Jensen",
  "afdeling": "Kardiologi",
  "tid": "13:15"
}
JSON = et dataformat
  • Bruger feltnavne og værdier
  • Er kompakt og let at behandle
  • Ses ofte i moderne API’er
JSON fortæller, hvordan data skrives – ikke hvem der må hente dem.

16 · REST

REST: en udbredt måde at bygge API’er på

  • En arkitekturstil – ikke et dataformat
  • Bruger typisk webteknologi (HTTP)
  • Ses ofte sammen med JSON
  • Typisk: hent, opret, opdater og slet
Forenklet eksempel
GET /aftaler/A-1042

Svar:
{ "tid": "13:15" }

“Hent oplysninger om denne aftale.”

17 · SOAP

SOAP: en mere formelt defineret beskedprotokol

  • En protokol med faste regler
  • SOAP-beskeder bruger XML
  • Kan have standardiserede mekanismer til bl.a. sikkerhed og fejl
  • Ses også i store og etablerede integrationslandskaber
Forenklet eksempel
<Envelope>
  <Body>
    <HentAftale>
      A-1042
    </HentAftale>
  </Body>
</Envelope>

Illustration, ikke en komplet SOAP-besked.
